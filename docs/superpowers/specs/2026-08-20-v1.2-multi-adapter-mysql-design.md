# V1.2 Phase 2 — Multi-Adapter SQL (MySQL) Design

Date: 2026-08-20
Status: Approved (brainstorming session)
Scope: V1.2 "Support Multiple Adapter DB", revised during brainstorming:
MongoDB is DROPPED — SQL only, MySQL first. Postgres remains; the adapter
layer stays open for future SQL (and, if ever needed, non-SQL) adapters.

## Context & Requirements

Ku-CRUD's data layer (`internal/ds`) is hardwired Postgres: pgx DSN,
`information_schema` + pg_catalog introspection, `"ident"` quoting, `$n`
placeholders, `ILIKE`/`::text` search. Handlers build SQL via `ds.Build*`
and execute through `*sql.DB` directly.

Decisions from the brainstorming session:

1. **Scope**: Postgres + MySQL. MongoDB removed from V1.2.
2. **Core requirement (user's words)**: adding a future adapter must NOT
   require changing existing queries. Query generation AND execution are
   owned by the adapter; the API layer speaks only neutral structures.
3. **Architecture (Option C — hybrid)**: one public `Adapter` interface
   (the only thing handlers import) + an internal `sqlkit` shared SQL
   engine parameterized by a small dialect struct used by the SQL adapters.
4. **Adapter executes**: adapter methods return `[]map[string]any` /
   counts; handlers never see SQL strings, args, or `*sql.DB`.
5. Connections stay lazy (per-request open/close, existing `liveDB`
   pattern preserved as `liveAdapter`).

## Adapter contract (internal/ds/adapter.go)

```go
type Adapter interface {
    Ping() error
    ListTables() ([]TableInfo, error)
    InspectTable(schema, table string) ([]LiveColumn, error)

    ListRows(p ListParams) ([]map[string]any, error)
    CountRows(p ListParams) (int, error)
    FetchByKey(schema, table string, keyCols []string, keyVals []any, cols []string) ([]map[string]any, error)

    Insert(schema, table string, cols []string, vals []any) error
    UpdateByKey(schema, table string, setCols []string, setVals []any, keyCols []string, keyVals []any) (int64, error)
    DeleteByKey(schema, table string, keyCols []string, keyVals []any) (int64, error)

    FetchByRefValues(schema, table, refCol string, displayCols []string, vals []any) ([]map[string]any, error)
    CountByRefEq(schema, table, col string, val any) (int, error)

    IsFKViolation(err error) bool
    Close() error
}
```

- `ds.Open(d meta.Datasource) (Adapter, error)` — factory keyed on
  `d.Driver`; unknown driver returns a clear error.
- File layout in `internal/ds`: `adapter.go` (interface + factory),
  `sqlkit.go` (dialect struct, generic SQL builder, scan helpers —
  `scanTargets/deref/rowToMap` move here), `postgres.go`, `mysql.go`.
  `drift.go` (`CompareDrift`/`EffectiveType`) stays as-is — it operates on
  dialect-neutral `LiveColumn` values.
- The old `ds.Build*` functions and `ds.Connect` are removed; every call
  site (rows.go, tables.go, rels.go, datasources.go) migrates to the
  Adapter. `ds.QuoteIdent` allowlist stays (used by sqlkit and def
  validation).
- Returned values are already type-normalized per adapter (bytes→string,
  time.Time for datetimes) — handlers no longer scan rows manually.
- Future SQL adapter = one new dialect config (+ specifics) on sqlkit;
  future non-SQL adapter = standalone implementation of the interface.
  Either way: zero changes to existing handlers.

## Metadata & datasource API

Migration 5:

```sql
ALTER TABLE datasources ADD COLUMN driver TEXT NOT NULL DEFAULT 'postgres';
```

- `meta.Datasource` gains `Driver string` (json `driver`). Existing
  datasources become `postgres` automatically; old API payloads without
  `driver` remain valid (default `postgres`).
- API `dsInput` accepts `driver`; validation: value must be
  `"postgres" | "mysql"` (empty → `"postgres"`); anything else → 400
  `"unsupported driver"`. Output DTO includes `driver`.
- `handleDSTest` → `ds.Open` + `Ping`; connection failures surface as
  today (502 CONN).
- `handleDSTables`/`handleDSColumns` → `a.ListTables()` /
  `a.InspectTable(...)`. For MySQL, "schema" = the connected database name
  (single-schema scope, mirroring Postgres' system-schema exclusion).

Not done (YAGNI): multi-host/replica options, advanced TLS options. The
shared host/port/db/user/password/sslmode form serves both drivers; for
MySQL `sslmode=disable` maps to `tls=false`, any other value to `tls=true`.

## MySQL dialect (mysql.go + sqlkit config)

**Driver**: `github.com/go-sql-driver/mysql`. DSN:
`user:pass@tcp(host:port)/dbname?parseTime=true&charset=utf8mb4[&tls=true]`
— `parseTime=true` so DATE/DATETIME/TIMESTAMP scan as `time.Time`
(JSON serialization consistent with pgx).

**Introspection** (information_schema, connected DB only):

- Tables: `WHERE table_type='BASE TABLE' AND table_schema=DATABASE()`
- Columns: `information_schema.columns`; PK detection via
  `table_constraints`/`key_column_usage` (same pattern as Postgres)
- Enums: `data_type='enum'` → parse `COLUMN_TYPE` `enum('a','b','c')`
- Type mapping: `tinyint(1)`→boolean; other
  tinyint/smallint/mediumint/int/bigint/decimal/float/double→number;
  date/datetime/timestamp/time→datetime; char/varchar/text variants→text;
  enum→enum

**sqlkit dialect differences swallowed:**

| Aspect          | postgres                     | mysql                                  |
|-----------------|------------------------------|----------------------------------------|
| Quote ident     | `"col"`                      | `` `col` `` (same allowlist regex)     |
| Placeholder     | `$1..$n`                     | `?` everywhere                          |
| Search          | `col::text ILIKE $n`         | `CAST(col AS CHAR) LIKE ?` (default ci collation ≈ ILIKE) |
| LIKE escape     | `\%`/`\_` + `ESCAPE '\\'`    | same (MySQL supports ESCAPE)            |
| FK violation    | pgconn code 23503            | `*mysql.MySQLError` Number 1451/1452    |

- `LIMIT ? OFFSET ?` shared by both.
- Drift verify/resync works automatically (built on `InspectTable`).
- Phase-1 relations (rels enrichment, picker, FK existence checks, delete
  protection) work across drivers via `FetchByRefValues`/`CountByRefEq` —
  including PG↔MySQL relations.

## Handler refactor (internal/api — one time, then untouched)

- `s.liveDB(dsID)` → `s.liveAdapter(dsID) (ds.Adapter, error)`; handlers
  `defer a.Close()`.
- Call-site migrations: `db.Query(BuildList(...), args...)` →
  `a.ListRows(lp)`; `fetchRows` → `a.FetchByKey`; `checkFKValues`,
  `referencedBy`, `buildRels`, `handleFKOptions` → Adapter calls;
  `fkViolation(err)` → `a.IsFKViolation(err)`.
- Error taxonomy unchanged: 400 VALIDATION / 403 FORBIDDEN / 404
  NOT_FOUND / 409 CONFLICT / 502 CONN with the same codes and shapes.
- `scanTargets/deref/rowToMap` move into sqlkit (adapters may adjust
  value conversion).

## Frontend (web/)

- `Datasources.tsx`: **Driver** dropdown (PostgreSQL/MySQL); switching the
  driver resets the default port (5432/3306). `Datasource` type gains
  `driver`.
- Everything else unchanged: TableForm (for MySQL schema = dbname), grid,
  rels display, picker, delete UX are driver-neutral.

## Testing & infrastructure

- `docker-compose.yml` gains a `mysql:8` service (host port 3307, user
  `ku`/`ku`, database `ku`).
- Integration env var: `KUCRUD_TEST_MYSQL` (self-skip when unset, same
  pattern as `KUCRUD_TEST_PG`).
- sqlkit unit tests (no DB): placeholder/quoting/search generation for
  both dialects; MySQL enum parsing; type mapping.
- MySQL integration tests: connect+ping, introspection (tables/columns/
  PK/enum), full row CRUD (search/sort/pagination), drift+resync, FK
  rels + delete protection 409 including a cross-driver relation (MySQL
  def → Postgres target), MySQL FK violation → 409.
- Full PG regression suite + `npm run build` / `npm run lint` stay green.

## Out of scope

- MongoDB support (dropped from V1.2).
- Third SQL adapter implementation (sqlite/mssql) — only the seam is kept
  open.
- Advanced TLS/CA configuration per datasource.
- Connection pooling/caching beyond per-request open (brief's lazy-connect
  requirement is already met).
